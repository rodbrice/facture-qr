# B2 validation record

Unit B2: the HTTP API over the invoice model (customers, invoices with lines, issue, mark as paid, list), ProblemDetails errors, validation at the boundary, structured logs, `/health`, the OpenAPI document and the invoice PDF with its QR-bill. The design and its reasons are in [ADR-0004](../adr/0004-http-api.md). All commands are run from the repository root.

## 4. Second check of the PDF with another decoder

Besides the automated test, the PDF of section 3 was rendered at 300 dpi with PyMuPDF and decoded with zxing-cpp (Python binding), the decoder used for the B0 samples. It found one QR Code whose text is:

```text
SPC / 0200 / 1 / CH4431999123000889012 / S / Max Muster & Söhne / Musterstrasse / 123 / 8000 / Seldwyla / CH /
(7 empty lines) / 1200.00 / CHF / S / Simon Muster / Musterstrasse / 1 / 8000 / Seldwyla / CH /
QRR / 000000000000000202600000015 / Facture 2026-0001 / EPD
```

(lines separated by ` / ` here). The account, amount, debtor, reference (the number `2026-0001` as `20260000001` with check digit 5) and message are those of the invoice. The page is A4 (595.28 × 841.89 pt) and has one page.

Validation of an invoice QR code in the SIX portal is not part of this unit; the payment part is produced by the same validated code path as the B0 samples (see `docs/validation/B0.md`).
